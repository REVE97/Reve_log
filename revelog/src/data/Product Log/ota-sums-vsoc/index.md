## ✅ 용어 정리

- **OTA (Over-The-Air)** : 차량의 **소프트웨어/펌웨어를 원격 업데이트**하는 기술
- **SUMS (Software Update Management System)** : **업데이트 배포**, **버전/이력 관리**, **상태 수집** 시스템
- **VSOC (Vehicle Security Operation Center)** : 차량의 OTA 상태와 **이벤트를 실시간 모니터링**하고 대응하는 관제/운영 센터
- **KATRI (한국교통안전공단 자동차안전연구원)** : OTA 업데이트가 안전에 영향을 주는지, 법규를 위반하지 않는지 검증해주는 기관 → **OTA 배포전 신고하는 과정**
- **ECU - Electronic Control Unit** : 차량 안에 특정 기능을 전담에 제어하는 소형 컴퓨터

---

## 🧭 플랫폼 서비스 시나리오

1. 타타대우 상용차의 **ECU (Electronic Control Unit)** 기반 데이터를 수집  
2. **VSOC**에서 차량의 OTA 상태/이벤트를 **실시간 모니터링**  
3. 문제가 발생하면 **Xenlink 플랫폼**을 통해 **SUMS로 데이터 전달**  
4. 이슈 해결을 위해 **KATRI에 관련 업데이트 내용을 신고/관리**  
5. **OTA 업데이트**로 대상 차량의 소프트웨어를 **원격 배포/적용**하여 문제 해결

# 🗓️ 2026.01.20 ~ 2026.02.04

## 개발 내용
- **HTML 기반** 퍼블리싱된 페이지, OTA/SUMS의 Vue 버전은 **Option API 기반 코드**가 많아  
  공통 컴포넌트 구조, API 호출 방식, Router/Modal/Pinia 등 **의존 관계를 우선 파악**했습니다.
- 본격 개발 전, KT 본사에서 개발 기기 보안 프로그램 설치 및 깃허브 접근권한 신청을 진행했고  
  **요구사항 명세서 / UI 시나리오 / GUI 명세서**를 확인했습니다.
- VSOC 관련 페이지 UI는 대부분 구성되어 있어, 각 화면에서 **Axios + REST API 연동을 통해**
  조회/필터링/등록/수정/삭제 흐름을 테스트하고, 화면 출력 형태(테이블/카드)를 정리했습니다.

## 개발 후기
- 기존에는 라우팅 시 하위 컴포넌트를 개별 선언해 관리했는데,  
  이번 프로젝트는 **children route**를 활용해 라우팅 구조를 정리하여 **가독성과 유지보수성이 개선**되는 것을 체감했습니다.
- UI 개편이 잦아지면서 API 응답 데이터를 `map`, `filter`, `findIndex` 등으로 가공해  
  **테이블/카드 형태로 출력**하는 패턴을 반복적으로 다뤘고,
  `select/option`, `input type="date|radio|time"` 등 폼 요소의 **양방향 바인딩/필터링**을 집중적으로 테스트했습니다.
- 기존 코드를 “새로 만드는 것”보다 “이해하고 이어가는 것”에 더 많은 시간이 들어갔고,  
  그 과정에서 **코드 리뷰/레거시 파악의 중요성**과 기본기(HTML 속성/JS 메서드)의 중요성을 다시 느꼈습니다.

## 향후 개발
- 개인정보가 포함된 DB API를 다루는 구간이 있어 **AI 도구 사용이 제한**될 예정이며,  
  그만큼 설계/디버깅에 시간이 더 소요될 수 있습니다.
- 파일 업로드 API가 존재하여 **`multipart/form-data` 전송 로직**을 구현할 예정입니다.
- 조회 화면에서 **기간 검색(From~To), 최신순 정렬** 등 조건 필터링 로직을 개발할 예정입니다.
- 사용자 입력 제어를 위해 `readonly`, `required` 등 **폼 제약 조건**을 반영하고, 검증 흐름을 정리할 예정입니다.

## 개발 내용

## 개발 후기
- **백엔드 API 서버와 Axios + REST API로 통신**하면서 데이터를 호출하는 과정에서 **Axios.get 할때 params 값을 매개변수에 추가하여 호출**하고 데이터 서버에서 **json 값이 어떠한 형태를 가지고 전송되는지 미리 파악**하여 상태값의 **value에 오류없이 저장해야할 필요성**을 느꼈고 **`route.params` 값을 이용해서 동적 라우팅 페이지를 구성**하는 경험을 해보았다.
- **Axios.post 할때 서버가 필수로 요구하는 `headers` 값을 매개변수에 추가**하여 호출하거나 **반드시 post 하는 데이터 속성을 확인하는 과정이 필요**하다는 것을 느꼈다.
- 단순히 백엔드 API 서버에서 데이터를 받아 출력하는 것이 아니라 **데이터를 Parsing 하는 과정을 통해 데이터를 활용하기 용이**하게 만들거나 사용자의 UX 를 향상시킬 수 있게 데이터를 관리하는 과정을 진행해보았다.
- Vue3 라이브러리의 **생명 주기를 생각하지 않고 개발을 진행 중 데이터 랜더링 오류를 많이 접하면서** **Optional Chaining 과 같은 데이터 처리를 진행**하면서 단순히 코드만 작성하는 것이 아니라 **라이브러리에서 코드가 작동하는 원리를 생각**하게 되었다.

## 향후 개발
- 현재 KATRI 신고 관련 페이지 UI에 API를 연동하는 과정을 진행 중이며 KATRI 신고서 갱신, 종료 페이지 API 연동을 진행할 예정이다.
- 개발 중 불필요한 코드 제거 및 최적화 작업, UI 시나리오에 맞는 데이터 Parsing 을 진행할 예정이다.

## 개발 후기
- 대략적인 전체 개발기능 구현 시나리오가 완성되는 시점에서 **GitHub를 통해 팀원들이 개발한 코드들을 `merge` 하는 과정에서 발생하는 오류들을 해결하면서 트러블슈팅에 대한 중요성**을 더욱 더 알게 되었다.
- 각 페이지를 동적 라우팅을 통해 이동하면서 **데이터를 랜더링,리랜더링 해야하는 프로젝트**인데 **`axios method`를 호출하고 데이터가 랜더링 되기 전 페이지가 이동되었을때 데이터가 추가 및 삭제되지 않고 새로고침 후 정상적으로 랜더링되는 현상이 발생**하여 **브라우저가 랜더링하는 과정을 공부**하는 시간을 가졌다.
- 기존에는 동적 라우팅 할때 **`<router-link>`, `router.push` 를 통해 `Http url` 방식에 `params` 값을 주어 이동하는 방식을 채택**하였는데 **프로젝트를 배포했을 때 `props` 를 무시하고 사용자가 `url` 를 직접 입력했을 때 오류가 발생할 수 있기 때문에 `name + params` 방식으로 리팩토링 진행**하면서 실무에 맞는 코드에 적응중이다.

## 향후 개발

- 로딩 스피너 모달 컴포넌트 개발하여 각 페이지에 적용 예정
